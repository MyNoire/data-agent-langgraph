# SQL 评测以内容匹配为主指标，严格执行匹配并列

QueryPilot 的结果是给用户和 Agent 里的大模型看的，对它们来说信息的形式无所谓，内容必须对。R5 的失败分析里，各组都答错的 29 道非冻结题有一半以上只是形式不同（多选了列、有重复行、姓名拼成一列、数字写成带 `%` 的字符串），严格执行匹配把它们算成错，掩盖了真正的错误。因此 SQL 评测的结论以 **Content Match（内容匹配）** 为准，**Strict Execution Match（严格执行匹配）** 保留原样，始终并列报告，用来和以前的结果及 BIRD 风格的数字对照。两者都不是官方 BIRD EX。

内容匹配只承认四种形式差异：预测结果可以多出列、列的顺序可以不同（列投影）；重复行不计（按行的集合比较）；文本值去掉末尾 `%` 后解析出的数字与金标准数值完全相等；一个文本列等于金标准几列用单个空格拼接的值（这几列可以按任意顺序拼接，在金标准里也不必相邻，例如 `'Harrison Sacha'` 覆盖"名、姓"两列）。数值要四舍五入才相等、比例和百分比换算、金标准的行数或形状不同，都不算。

## Consequences

- 忽略重复行会掩盖「少了一条重复事实」的错误，例如两笔各 6 美元的支出只列出一个 6；规则制定时在 R5 的结果里没有见到这种情况。
- 规则是看过 72 道非冻结题的失败之后定的，对所有题（包括冻结题）统一适用；不按单题增减规则。金标准有问题的题不剔除、不改标签，只在失败分析中注明。
