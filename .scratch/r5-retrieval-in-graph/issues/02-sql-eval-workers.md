# 02: SQL 评测并发

**What to build:** 评测开发者用 `eval graph --workers N` 同时跑多道题，报告内容和顺序与逐题运行相同，八次运行能在二十分钟左右跑完。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

沿用检索评测的主线程派发结构。

- [ ] `eval graph --workers N`，默认 1
- [ ] 工作线程里跑一道题的图和金标准 SQL；结果比对、逐题记录和进度事件都在主线程
- [ ] 同时在跑的题不超过 N 道，主线程处理完一道才提交下一道
- [ ] 单题的错误和现在一样记为 error 并继续；主线程自己出错或被中断时不再开始新题
- [ ] 报告的逐题记录按题集顺序排列，与哪题先跑完无关；`workers` 为 1 和大于 1 时，除耗时外报告相同
- [ ] 运行配置和报告记录线程数
- [ ] 确认编译好的图、运行上下文和日志中间件可以被多个线程同时使用；不行的部分改成每个线程各用一份，结论记在 Comments
- [ ] 测试用假 SQL 生成器，覆盖：报告顺序、`workers` 为 1 和 4 时结果相同、单题出错后继续、主线程出错后不再开始新题
- [ ] SQL 评测文档写明：`workers` 大于 1 时逐题耗时只在相同线程数的运行之间比较
