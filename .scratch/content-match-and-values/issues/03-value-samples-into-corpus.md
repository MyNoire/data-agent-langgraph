# 03: 取值样例进入 Corpus

**What to build:** 知识准备多出一步：只读打开业务 SQLite，按 Catalog 逐列取值，生成取值样例文件（规则 `value-samples-v1`，见规格「实现决定 / 取值样例」）。构建 Corpus 时可选地读入它，列 Chunk 在「取值解释」后多出一行取值，`corpus_id` 随之改变。隐私列由语义配置里的名单决定，在取值这一步就跳过，值不落盘。不给新输入时构建结果与今天逐字节相同。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 语义配置可选地带每个库的隐私列名单；旧格式配置照常可用
- [ ] 取值这一步用一个小测试 SQLite 验证：TEXT 且去重非空取值 ≤ 20、非主键 / 外键 → 全部取值按值排序；其他列 → 出现最多的 3 个非空值（同次数按值排序）；键列只给样例；超过 80 字符截断并标记；隐私列不取值且文件里不出现它的任何值
- [ ] 取值样例文件记录规则版本、来源 SQLite 的 sha256、库标识、每列的取值方式和取值；它放在 Git 忽略的目录下
- [ ] 构建 Corpus 时读入取值样例文件：它作为新的来源角色进入 Corpus 身份；列 Chunk 新增取值行（写明是全部取值及个数，还是样例）；隐私列不加这一行；用新的渲染版本标记
- [ ] 不给取值样例文件、语义配置也没有新字段时，构建出的 Corpus 与今天完全相同（有测试，或用现有快照比对）
- [ ] 取值样例文件与 Catalog 对不上（库不同、列不存在）时构建明确失败
- [ ] 提供命令行入口生成取值样例文件，知识库文档的流程图和步骤表补上这一步
- [ ] 隐私名单首版写进两个库的语义配置（student_club：`member.first_name`、`last_name`、`email`、`phone`；toxicology：无），交给用户审阅
- [ ] 模块边界测试和全部单元测试通过
