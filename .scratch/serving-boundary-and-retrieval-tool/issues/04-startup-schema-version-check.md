# 04: 启动时停用知识过期的库

**What to build:** 用户端启动时逐库核对业务库当前的 Schema Version。核对不通过的库只在本次启动中停用，模型经 tool 得到明确类别，其他库照常。见 [spec](../spec.md)「实现决定 / 启动核对」。

**Blocked by:** 02（检索 tool 的失败契约）

**Status:** ready-for-agent

**分工：** Claude 写结构核对和启动时的停用。tool 沿用 02 的映射；如果发现必须改 tool，停下交给用户。

**用户故事：** 6–10、37、44

- [ ] 核对使用与构建相同的算法；retrieval 对上提供核对，业务库位置由 querying 取得后传入，不新增 retrieval → databases 和 querying → knowledge 的依赖
- [ ] 测试：结构一致时可用；只改数据时仍可用
- [ ] 测试：给一个库加列后，它经 tool 返回 `knowledge_stale`、不重试，且不发起检索；另一个库照常
- [ ] 测试：未登记、文件不可用、提取失败、含有视图，各自只停用这个库，经 tool 返回 `database_unavailable`、不重试
- [ ] 核对只在启动时做一次，对业务库只读
- [ ] 对两个正式库只读核对一次，都与 Active Corpus 一致，记录命令与结果；不调用付费服务
- [ ] 文档写明它发现不了运行中的改表和只改数据造成的取值样例过期；面试材料里的状态同步
- [ ] 架构测试和全部单元测试（不含集成测试）通过，记录实际命令与结果
