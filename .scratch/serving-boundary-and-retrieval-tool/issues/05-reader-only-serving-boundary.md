# 05: 用户端只凭 reader 运行，够不到管理操作

**What to build:** 用户端只有 reader 连接串也能经 tool 检索；用户端代码一旦误导入管理操作，架构测试就失败。知识管理命令和评测照常可用。见 [spec](../spec.md)「实现决定 / 只读配置与导入边界」。

**Blocked by:** 01（检索 tool 的最小成功路径）

**Status:** ready-for-agent

**分工：** Claude 写只读配置、边界检查和集成测试。tool 不改；如果发现必须改 tool，停下交给用户。

**用户故事：** 15、17–22、44

- [ ] 只读配置类型只含 reader 连接串和读取所需的超时；打开只读会话和检索只依赖它
- [ ] 管理命令和评测沿用现有配置、照常可用；不做“发现 admin 连接串就拒绝启动”
- [ ] 集成测试：在专用测试库上只给 reader 连接串，用假 Embedder 和假 Reranker 经 tool 检索成功
- [ ] 测试：合成源码里 retrieval 导入构建、导入、校验等管理操作时被报告
- [ ] 测试：合成源码里整模块导入 knowledge 的各种写法都被报告，不能绕过按名字的限制
- [ ] 测试：合成源码里 HTTP 或 `query` 命令导入 knowledge、evaluation 时被报告
- [ ] 现有生产源码通过边界检查
- [ ] 文档写明只读配置和静态检查不是进程级隔离，部署时只下发 reader 凭据；面试材料里的状态同步
- [ ] 架构测试、全部单元测试和知识库集成测试通过，记录实际命令与结果
